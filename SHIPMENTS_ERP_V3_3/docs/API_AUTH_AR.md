# SHIPMENTS ERP V3.3 — المصادقة والصلاحيات (نسخة تجريبية)

## ما تمت إضافته
- دخول باسم مستخدم وكلمة مرور، مع تخزين كلمة المرور باستخدام PBKDF2-HMAC-SHA256 وملح عشوائي.
- رمز وصول موقّع قصير العمر، والتحقق من حالة المستخدم في قاعدة البيانات عند كل طلب محمي.
- أدوار: `super_admin`, `company_manager`, `branch_manager`, `treasury`, `auditor`, `courier`.
- إنشاء مستخدمين بواسطة مدير النظام فقط.
- صلاحيات منفصلة للقراءة والكتابة والعكس وسجل التدقيق.
- تقييد مدير الفرع بفرعه، والمندوب بدفتر عهدته فقط.
- سجل تدقيق يسجل الدخول وإنشاء المستخدمين وحركات العهدة والقيود العكسية.
- واجهات دفتر العهدة تتطلب Bearer token؛ لا يوجد تجاوز تلقائي للمصادقة.

## تشغيل محلي
```bash
python -m venv .venv
# Windows PowerShell: .venv\\Scripts\\Activate.ps1
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

اضبط متغيرات البيئة قبل تشغيل الخادم. استخدم كلمات مرور وأسرارًا جديدة خاصة بك، ولا تضعها في GitHub:

```text
SHIPMENTS_LEDGER_DB=./backend/ledger_demo.sqlite3
SHIPMENTS_AUTH_SECRET=ضع_هنا_قيمة_عشوائية_طويلة_وفريدة
SHIPMENTS_BOOTSTRAP_ADMIN_USER=admin
SHIPMENTS_BOOTSTRAP_ADMIN_PASSWORD=كلمة_مرور_قوية_لا_تقل_عن_12_حرفا
SHIPMENTS_TOKEN_TTL=3600
```

ثم شغّل:
```bash
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

يُنشأ حساب المدير الأول مرة واحدة عند بدء التشغيل إذا كانت متغيرات التهيئة موجودة ولم يوجد الحساب. لا يوجد تسجيل عام مفتوح.

## الواجهات
- `POST /v1/auth/login` — JSON: `username`, `password`.
- `GET /v1/auth/me` — بيانات الحساب والصلاحيات.
- `POST /v1/admin/users` — إنشاء مستخدم (مدير النظام فقط).
- `GET /v1/admin/audit?limit=100` — قراءة سجل التدقيق (مدير النظام/مدير الشركة).
- `POST /v1/couriers/ledger` — إضافة حركة عهدة حسب الدور.
- `GET /v1/couriers/{courier_code}/ledger` — قراءة دفتر العهدة.
- `POST /v1/couriers/ledger/{reference_no}/reverse` — قيد عكسي (مدير النظام/مدير الشركة).

أرسل الرمز في ترويسة `Authorization: Bearer <access_token>`.

## مصفوفة الصلاحيات
| الدور | قراءة العهدة | إضافة حركة | عكس حركة | إدارة المستخدمين | سجل التدقيق |
|---|---:|---:|---:|---:|---:|
| super_admin | نعم | نعم | نعم | نعم | نعم |
| company_manager | نعم | نعم | نعم | لا | نعم |
| branch_manager | فرعه فقط | فرعه فقط | فرعه فقط | لا | لا |
| treasury | نعم | توريد فقط | لا | لا | لا |
| auditor | نعم | لا | لا | لا | نعم |
| courier | عهدته فقط | لا | لا | لا | لا |

## حدود مهمة قبل الإنتاج
- هذه النسخة تشغّل API على SQLite محليًا؛ ملف PostgreSQL في `backend/schema.sql` مخطط جاهز للمراجعة، وليس اتصالًا حيًا بقاعدة سحابية.
- واجهة `index.html` ما زالت نموذج عرض محليًا، ولم يتم ربطها بواجهات الدخول أو API في هذه النسخة.
- الرمز الافتراضي في الكود مخصص للتجربة فقط. يجب تعيين `SHIPMENTS_AUTH_SECRET` عشوائيًا وسريًا، وتفعيل HTTPS، وتخزين الأسرار في مدير أسرار، وتدويرها قبل أي نشر.
- يلزم إضافة تحديد معدل محاولات الدخول، وسياسة قفل الحساب، وإدارة جلسات/إلغاء الرموز، ومراجعة أمنية مستقلة.
- لا تستخدم بيانات مالية حقيقية أو تعتمد تسويات حقيقية بهذه النسخة.
